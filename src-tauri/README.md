# Native shell spike backend

Owned implementation: Tauri v2, one `main` window, Windows MSVC target. Build/check from this directory with `check-vs2022.cmd check --target x86_64-pc-windows-msvc` (or `build --release`). The wrapper explicitly selects VS 2022 v17, not VS18. The configured Tauri hooks run `npm run dev` / `npm run build` with `cwd: ../frontend`; Vite uses port 1420. Production Cargo builds enable the `custom-protocol` feature by default.

## Adapter integration

Invoke `get_runtime_info`, `set_window_appearance` with `{ appearance: { background_kind, color_rgba: "#RRGGBBAA", window_alpha: 0..100 } }`, and `open_background_file` with `{ kind: "image" | "video" }`. Tauri commands resolve their typed success payload and reject with `{code,user_message,recoverable}`. Runtime has `interface_version: 1`. Cancellation resolves `{status:"cancelled"}`.

Use `http://background.localhost/<asset_id>` for a selected background on Windows. This is a custom Tauri URI scheme registered in Rust, not Tauri's broadly scoped asset protocol. Only the currently selected random UUID maps to an already-open read-only file handle. No file path is sent to JavaScript; selecting another file revokes the previous URL. No directory access, arbitrary URL-to-path conversion, shell plugin, or filesystem plugin is enabled. GET/HEAD only, no query strings, up to 8 MiB per byte-range response, and a 64 MiB maximum for ordinary responses. Images are limited to 8 MiB and videos to 64 MiB. PNG/JPEG/WebP headers are parsed with `image` before a URL is issued; each image is capped at 16,384 pixels per side and 16 megapixels total. The extension/MIME allowlist is PNG/JPEG/WebP/MP4/WebM. Failed or cancelled selection keeps the previous handle; frontend must show a solid fallback and visible error when decoding fails.

The UI must listen for `window_visibility_changed` with `{is_visible}` and combine it with `document.visibilitychange` and background-layer visibility to pause video. Native resize/focus events report minimized/visible state; native hide without either event is not independently observable here. Video must be muted. Validated image width/height are returned; video dimensions and duration are not extracted. WebView decode errors must restore the solid UI canvas and display a visible error: the backend does not validate codecs or fully decode media. File handles prevent a URL from later being redirected through a replaced path, but do not make selected content immutable.

The native window is undecorated and transparency-capable with a transparent startup backing. The custom header provides explicit drag, minimize, maximize/restore, and close actions through narrowly scoped window permissions. Solid mode sets the native backing opaque; transparent/image/video modes set backing alpha to zero. The frontend applies the canvas/media alpha once and keeps panel text/control opacity intact. Native setter failure attempts an opaque fallback and returns a structured error for non-solid modes. Successful setter calls do not prove Windows compositor support: visual desktop transparency remains unverified. No whole-window opacity or click-through is applied.

Provider discovery reads PATH and adjacent npm package manifests only. It never executes any CLI, including Claude or Codex. Installed versions are returned only when an adjacent matching npm package manifest provides them; standalone executables or other installation layouts can be found with version omitted. All six capability statuses remain unknown. No provider task is started.

## Packaging and basic validation

An installed Evergreen WebView2 Runtime is required for direct executable use. The configured future installer mode downloads its bootstrapper; bundling is disabled for this spike, so this does not prove clean-machine packaging. No installer or WebView2 runtime was tested.
